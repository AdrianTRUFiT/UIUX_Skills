# Dynamic Web Builder

This repository is a governed creative-production and frontend delivery system for Claude Code.

It combines:

- UI/UX Pro Max design intelligence;
- companion brand, design-system, styling, banner, and slide skills;
- visual-convergence workflow driven by rendered screenshots, not source-code confidence;
- creative-technology direction for motion, 3D, WebGL, cinematic and spatial experiences;
- showcase-product transformation for turning working repos into demonstrable digital assets;
- premium product engineering for usable operator workflows;
- 21st.dev Magic MCP and CLI component access;
- a commandable end-to-end build skill;
- dedicated build and experience-direction agents;
- Playwright CLI browser verification;
- Windows and Claude Code cloud installation paths.

## What the system is for

Use it when the requested outcome is a working website, application page, dashboard, portal, form workflow, interactive product surface, immersive experience, or showcase-grade digital product.

It does not treat any of the following as completion:

- a static mockup;
- a screenshot recreation that does not work;
- a disconnected component gallery;
- dead buttons or fake links;
- hardcoded success behavior;
- code that compiles but has not been operated in a browser;
- a technically correct interface that remains visibly generic or below the defined visual standard.

The full creative-production loop is:

```text
Product Truth
→ Creative Direction
→ Visual Target
→ Experience Concept
→ Implement
→ Render
→ Compare
→ Critique
→ Correct
→ Operate
→ Verify
→ Showcase Proof
→ Human Review
```

The critical rule is that visual quality must be judged from the rendered product. Lint, build, tests, and proof gates are necessary but cannot prove hierarchy, composition, distinctiveness, or perceived product quality.

## How to direct high-quality work

For a normal functional build:

```text
/build-dynamic-web Build <the complete functional outcome>
```

For premium transformation work, provide the working repository plus visual references and state the product outcome in plain creative-director language. The system should first establish product truth and the visual target, then use visual convergence after rendering.

For sophisticated interactive work, describe the intended experience rather than guessing the library. `creative-technology-direction` should translate intent into the appropriate level of CSS/SVG, Motion/GSAP, Canvas, Three.js/React Three Fiber, shaders, media, or other browser technology.

For portfolio/showcase work, the goal is not decorative spectacle. The system should expose the strongest real capability through a short, understandable demonstration journey and one product-specific signature moment.

## Windows installation

From PowerShell:

```powershell
Set-Location "D:\DEV\UIUX_Skills"
git fetch origin
git switch claude/dynamic-web-builder-v1
git pull --ff-only
Set-ExecutionPolicy -Scope Process Bypass -Force
.\install-dynamic-web-builder.ps1
```

Then enter any application repository and run:

```powershell
dynamic-web
```

## Delivery authority

UI/UX Pro Max supplies design intelligence. Visual Convergence supplies rendered visual correction. Creative Technology Direction supplies modern interaction vocabulary and appropriate implementation selection. Premium Product Engineering supplies product-quality discipline. Showcase Product supplies demonstration strategy. 21st.dev supplies optional component discovery and generation. Playwright supplies browser operation. Claude Code remains responsible for integrating real routes, state, data, persistence, validation, loading, empty, success, error, responsive, accessibility, test, build, and GitHub delivery behavior.

Repository truth and project governance outrank all reusable skills.

No branch may be merged without explicit human authorization.
